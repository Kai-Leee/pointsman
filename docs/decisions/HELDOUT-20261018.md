## 정상 대조 후보와 숨김 자료 경계

openapi 대조 증거(`benchmark-runs/d071-preflight/public-controls-v4.json`, [D071_PREFLIGHT](../agents/D071_PREFLIGHT.md))와 같은 방식이다. 정상 대조는 저자가 쓴 일부러 불완전한 구현이고, 결함 대조는 그 구현의 변이다. 새 감사 모듈 `scripts/audit-task-public-checks.mjs`의 `auditPublicChecks({controls: true})`가 고정 image, network none, 읽기 전용 mount, tmpfs로 Docker 대조를 한 번 돌렸다. 그 receipt를 `wx`(덮어쓰기 금지)로 기록했다.

- **정상 대조 후보:** 과제마다 `public-checks/controls/reference/`. Claude 서브에이전트 1개가 과제당 하나씩 `instruction.md`만 명세로 삼아 썼다. h2 Python 525줄·7파일(hyperframe/hpack 위), pycparser 1,116줄·5파일(표준 라이브러리, 손으로 쓴 재귀 하강 파서), modelcluster 1,117줄·8파일(Django 5.2/taggit 6.1 위). 각자 `pyproject.toml`과 오프라인 editable install `setup.sh`를 둔다.
- **결함 대조:** `controls/defects.json`의 정확한 텍스트 치환(각 `old`는 한 번만 일치)과 `controls/catalog.json`의 기대 실패 ID. 준비 계획의 결함 52/53/88개를 이름과 기대 ID 그대로 유지했다. 구현 방식만 바뀐 항목과 이유는 각 `controls/NOTES.md`에 있다.
- **숨김 내용이 새지 않는 근거:**
  1. 작성 입력은 `instruction.md`, 같은 문서에서 만든 `atoms.json`/`obligations.json`/`public-checks.plan.json`, 고정된 harness 파일뿐이었다. `tests/`, `solution/`, `environment/`, `grade.json`(숨김 검사 파일명과 해시 포함)은 열지 말라고 지시했다. 세 서브에이전트가 보고에서 열지 않았다고 밝혔다.
  2. 이 세션이 결과물에서 숨김 경로 참조(`tests/`, `solution/`, `environment/`, `grade.json`)를 `rg`로 찾았다. 일치는 "읽지 않았다"고 적은 NOTES 문장뿐이었다.
  3. 세 image에는 의존성만 있고 과제 패키지(h2, pycparser, modelcluster)는 없다(`importlib.metadata` 목록으로 측정). image에서 정답을 얻을 경로가 없다.
  4. modelcluster 작성자는 Django/taggit API 확인을 위해 image 안의 그 두 패키지 소스만 읽었다.
- **한계:** 1·4는 서브에이전트의 자기 보고다. 이 세션은 파일 접근 기록을 따로 감사하지 않았다. 모델이 공개된 upstream 프로젝트에 대해 사전에 알던 지식이 참조 구현에 섞였을 가능성은 배제하지 못한다. 그 영향은 대조 구현에 한정된다. 후보 작업자는 `/checker`를 읽지 못하고 공개 검사 실패 메시지만 받는다.
