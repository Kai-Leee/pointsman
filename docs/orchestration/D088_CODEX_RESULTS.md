## 판단 절감이 전체 절감으로 이어졌는가

[초기 입력·호출 시간 대조](../../benchmark-runs/d088-codex-20261016-01/initial-planning-audit.json)에서 요청 4개가 저장 바이트와 canonical SHA 모두 일치했다. 질문 수는 53+53+53+51=210이다. 이 호출 영수증의 시간 합은 **Codex 273.436596초·Jev 8.768447초**, 차이는 **31.184배**다. Codex CLI와 Jev 측정 wrapper 시간이며 순수 모델 추론·HTTP·제품 완료 시간 비교가 아니다. 시작→계획 commit은 277.931724초/12.607437초로 환경 검사와 제어기 부가시간도 포함한다.

| 구성 | Codex 판단 조건 | Jev 판단 조건 | 차이 |
|---|---:|---:|---:|
| 초기·수리를 합친 판단 토큰 | 271,588 | 234,954 | −36,634 |
| 작업자 토큰 | 390,934 | 607,879 | +216,945 |
| 판단 참고 환산액 | $1.3170592 | $0.1279578 | −90.28% |
| 작업자 참고 환산액 | $2.613928 | $3.631596 | +38.93% |

판단에서 줄인 양보다 작업자 수리에서 늘어난 양이 컸다. **216,945−36,634=180,311토큰 증가**다. 판단 비용 절감액 $1.1891014 중 작업자 비용 증가 $1.017668이 상쇄해 전체 참고 절감은 4.36%에 그쳤다. 이는 실제 호출·usage의 산술 분해다. 특정 Jev 답변 하나가 재호출 증가를 일으켰다고 입증한 것은 아니다.

비용식은 Codex `((input−cached_input)×4+cached_input×0.4+output×20)/1e6`, Jev `paid_input×0.6/1e6`다. Jev 조건은 Codex 작업자 $3.631596+Jev 토큰팩 참고액 $0.1279578=$3.7595538이다. [공식 Codex 단가](https://developers.openai.com/api/docs/pricing)와 [Jev 과금 규칙](https://jev-ai.pro/docs)을 확인했다. 요청 프로필의 표준·짧은 문맥 시나리오이며 실제 served identity·tier·context band·cache-write 추가 과금은 확인되지 않았다. Jev의 $0.6/M은 역사적 토큰팩 참고 단가이며 현재 월정액의 실제 사용분 배분액이 아니다.

긴 문맥·표준 시나리오는 Codex $7.0395244, Jev $6.491542+$0.1279578=$6.6194998이다. 이는 오차 구간이 아닌 다른 단가 조건이다. 엄격한 API 환산 총액과 실제 구독 청구·배분액은 `null`이다.

## 남은 실패와 보존

Jev 최종 공개 실패는 `public.schema-models / T.R10.03` 한 건이다. 메시지는 “Google sections are separated by blank lines”로, Google 형식 docstring의 섹션 사이 빈 줄 조건이 남았다. 독립 실패 4건의 상세는 개발 입력으로 읽지 않았고 같은 원인이라고 단정하지 않는다. Codex의 공개 실패 12건은 docstring·타입·description 관련이며 정확한 case ID는 감사 JSON에 남았다. 종료 뒤 추가 수리는 하지 않았다.

이번 Jev 응답은 `typesafe-ai/jev`와 `jev-1.13.0`이었다. dated 1.14가 새 실행에서 관측되지는 않아 1.14 실전 성공으로 보고하지 않는다. 1.14 입력 허용·정산 일치는 실제 D087 입력의 무과금 재생과 native 장부 통합 fixture로 검증했다.

[보존한 D087 감사 사본](../../benchmark-runs/d088-codex-20261016-01/prior-d087-audit.json)도 남았다. D087 Codex는 공개 82/93·독립 59/63·20분 56.301초·628,014토큰이었다. D087 Jev는 2POST 뒤 입력 검사에서 중단돼 작업자·공개·독립 검사가 미실행이었고 9.611초·83,665토큰이었다. 새 D088 Jev는 6POST·작업자 12회와 전체 검사까지 실행했다. 중단 접두 구간의 시간·비용을 완료 효율과 비교하지 않는다.

원래 장부 ID를 유지했고, 입력 213,263토큰·정산 6건 증가가 영수증과 일치한다. pending 0·blocked `null`이다. live 장부와 Finder 메타데이터를 제외한 **과거 49,220개 파일의 변경은 0**이다. 실행 중 기능 소스 414개도 변경 0이다. 임시 CLI HOME은 제거됐으며 실행 전후 기존 컨테이너 5개의 ID·이름·이미지가 같다. Docker는 실행 상태를 유지했다.

새 실행·검사 프로세스는 종료됐다. 코드·문서·원시 결과는 새 로컬 worktree에 미커밋으로 남는다. 기존 보류 채점은 재개하지 않았고 커밋·푸시는 하지 않았다. 중간 모니터가 완료 영수증만 세어 진행 중 호출을 놓친 표현은 대화에서 정정했다. 최종 집계는 원본 호출 영수증 34건 전체를 대조했다.

다음 해결 대상은 남은 공개 형식 실패와 수리 호출·입력 증가다. 새 변경과 새 측정으로 다루며 이번 종료 디렉터리는 재개하지 않는다.
